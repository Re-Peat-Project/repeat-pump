What it does

You give it a bare-earth elevation model (DTM), the canal network, peat and burn maps, and the priority sub-KHGs. It then works in 11 stages, which the computer runs one after another:

1 Load›2 Clean canals›3 Flow›4 Segments›5 Land profiles› 6 Prioritise›7 Sekat›8 Network›9 Routing›10 Pumps›11 Report

Red stages are review stops: the tool pauses so that you can look at the result and approve it before it continues (see Review stops).

What you end up withA GeoPackage (.gpkg) of map layers you open in QGIS, plus a written report (run_report.md). Canals ranked by need, proposed sekat locations and heights, water source points, pump routes, pump stations with their power, and the gates you must add.

Fungsi alat ini

Anda memberikan model ketinggian permukaan tanah (DTM), jaringan kanal, peta gambut dan kebakaran, serta sub-KHG prioritas. Alat ini lalu bekerja dalam 11 tahap yang dijalankan komputer satu per satu:

1 Muat›2 Bersihkan kanal›3 Aliran›4 Segmen›5 Profil lahan› 6 Prioritasi›7 Sekat›8 Jaringan›9 Rute›10 Pompa›11 Laporan

Tahap berwarna merah adalah titik tinjauan: alat berhenti agar Anda dapat memeriksa hasilnya dan menyetujuinya sebelum melanjutkan (lihat Titik tinjauan).

Hasil akhirSebuah GeoPackage (.gpkg) berisi layer peta yang Anda buka di QGIS, ditambah laporan tertulis (run_report.md). Isinya kanal yang diurutkan menurut kebutuhan, lokasi dan tinggi sekat usulan, titik sumber air, rute pompa, stasiun pompa beserta dayanya, dan pintu air yang harus Anda tambahkan.

Stage by stage: what each one reads and produces

Read it from top to bottom. Each stage uses the layers produced by the stages above it, so a mistake early on carries down. Layer names are the ones you will see in the output GeoPackage.

Two things to noticeThe original DTM is used for all heights and slopes (stages 5 and 7); the "burned" copy from stage 3 is used only for flow. And the canal layer you review in stage 2 (canals_clean) is the base of almost everything after it.

Tahap demi tahap: apa yang dibaca dan dihasilkan

Bacalah dari atas ke bawah. Setiap tahap memakai layer yang dihasilkan tahap di atasnya, jadi kesalahan di awal terbawa ke bawah. Nama layer adalah nama yang akan Anda lihat di GeoPackage keluaran.

Dua hal yang perlu diperhatikanDTM asli dipakai untuk semua tinggi dan kemiringan (tahap 5 dan 7); salinan yang "dibakar" dari tahap 3 hanya dipakai untuk aliran. Dan layer kanal yang Anda tinjau di tahap 2 (canals_clean) menjadi dasar hampir semua tahap sesudahnya.

Before you start

  1. QGIS 4 with the RE-PEAT Pompanisasi plugin installed and enabled. Step-by-step instructions, in English and Bahasa Indonesia, are in install.html.
  2. Internet for the first engine setup, and again the first time stage 3 runs, when the tool downloads the WhiteboxTools program. After that it works offline.
  3. Python 3.11 or newer (from python.org) installed on the computer. The plugin uses it to build its own private environment, so you do not touch Python yourself.
  4. Your data prepared as in Input data, all saved as files (GeoPackage, Shapefile, GeoTIFF). Temporary layers do not work.
  5. A config file (.yaml) filled in by the person responsible for the decisions in The config file.
Want to practise first?There is a small set of dummy data and a full wizard guide with screenshots: wizard.html.

Input data

Use one projected coordinate system in metres for everything (for example UTM 49S, EPSG:32749). Mixed systems are the most common mistake; the tool stops with an error if a layer does not match.

The config file

A small text file (.yaml) holds the file paths and the decisions only a person should make. Start from configs/example_khg.yaml. Every value left as null is a decision still to be made. The tool never guesses: if a stage needs one, it stops and lists every missing value in one message.

Running it

In QGIS with the guided wizard (recommended)

The wizard takes you through the 11 stages one at a time. Install the plugin first (see install.html), then:

  1. Open the wizard with the water-drop button on the toolbar, or Plugins › RE-PEAT Pompanisasi › Guided wizard. If it asks for the engine, click Set up engine and wait a few minutes.
  2. On stage 1, open Run setup. Choose the output GeoPackage, a starting config, the priority table (CSV) and each input layer, then click Create run. The run folder is the folder of the GeoPackage; your settings are saved there in run_config.yaml.
  3. Each stage card has a Decisions box with the settings that stage needs. Empty ones are highlighted and the Run button stays off until you fill them. The wizard never fills them in for you.
  4. Click Run stage. The result numbers appear on the card and the stage's layers are added to the map. QGIS stays usable while it runs, and Cancel run stops it.
  5. At a review stop (stages 2, 6 and 9) the card says Review needed. Look at the layers, then click Accept and continue (see Review stops).
  6. Turn on Learn mode (top right) to see what each stage does and why, with references. The EN and ID buttons switch between English and Bahasa Indonesia.

The full guide with screenshots and practice data: wizard.html.

Layers the form does not haveThe setup form has no slot for the concession layer or water-level observations. Add them to run_config.yaml by hand (see the commented lines in configs/example_khg.yaml); the wizard then marks stage 1 as out of date and you re-run from there.

In QGIS with the Processing algorithms

The same work is available as separate algorithms, useful for repeating only part of a run or for batch use.

  1. Open the Processing Toolbox and find RE-PEAT Pompanisasi.
  2. Choose Run full pipeline. Pick your config file, then each input layer. Choose where to save the output GeoPackage.
  3. Click Run. The very first run also builds the tool's private environment, which needs internet and takes a few minutes. This happens only once (you can also trigger it with Set up engine environment).
  4. The log window shows each stage. The result layers are added to your project when it finishes.

The other entries (stages 1-2, 3-5, 6, 7, 8-11) run a part of the work. They are useful to repeat only what you changed.

From the command line (optional)

python -m repeat_pump.cli run --config my_khg.yaml
python -m repeat_pump.cli run --config my_khg.yaml --accept 2 --accept 6 --accept 9

Exit code 0 = finished, 1 = error, 2 = waiting for your review.

The 11 stages

Each stage reads the result of the one before. Layer names below are the layers you find in the output GeoPackage. Files that are not map layers (rasters, logs) are in the folder named after the output file with _work added.

1 Load and validate

Checks that your data is usable and keeps only what is inside the chosen sub-KHGs.

Does
Refuses a DSM, checks the CRS of every layer, selects the sub-KHGs (top N by priority, by ID, or all; without a priority ranking every sub-KHG is selected with equal priority), cuts all data to them plus the margin, converts text attributes (burn frequency, peat class).
Output
subkhg_selected, inputs_clipped_* layers, a clipped DTM and moisture raster.
Check
The warnings list. Pay attention to the accuracy warning, to unreadable burn or peat values, and to layers that cover less than 90 % of the area.

2 Canal topology REVIEW

Cleans the canal lines so they form a connected network. Water routing only works on a connected network.

Does
Applies your canal edits, snaps nearly-touching ends together, splits lines at junctions, removes duplicates, trims short stubs (if switched on), and checks that every canal is connected to a river. Nothing is deleted without a record.
Output
canals_clean plus problem layers: qa_topology_gaps (ends that were snapped), qa_topology_dangles (free ends), qa_topology_disconnected (canals with no river connection), qa_topology_issues (self-crossing or closed lines), qa_topology_trimmed, qa_topology_edits.
Check
Open the problem layers. A gap too big to snap shows as dangles near another canal. Fix it by adding a line to your canal edits layer (action = add) or removing a wrong canal (action = delete), then run again. The same edits give the same result every time.

3 Flow analysis

Works out where water flows over the land, used only for routing.

Does
Burns the canals into a copy of the DTM, removes small pits, and calculates flow accumulation (how much land drains to each cell).
Output
Files dtm_conditioned.tif and flow_acc.tif in the work folder.
Check
The warning about canals that used the default depth, which means depth_m was missing. The original DTM is never changed; all heights and slopes come from it.

4 Segments

Cuts canals into pieces of at most 500 m, which are the units that get scored.

Output
canal_segments with a stable seg_id, length_m and status_mcda.
Check
Pieces shorter than 25 m get status_mcda = 0: they stay in the network but are not scored.

5 Land profiles and flow direction

Measures how the land rises along each canal.

Does
Reads land height on both banks (6 m and 10 m from the canal, because the canal bed itself is lower than the land), smooths it, derives slope, and decides which end of each canal is downstream. Flat canals are decided by their distance to the nearest river.
Output
canal_profiles (points every 5 m), and new fields on canal_segments (z_up_m, z_down_m, i_lahan_pct) and on canals_clean (direction).
Check
A warning about canals whose direction could not be resolved, usually canals not connected to any river.

6 Prioritise segments REVIEW

Ranks segments by how much they need rewetting.

Does
For each segment takes the burn class and peat class that cover the greatest length of the segment, measures dryness in a ring around the canal (excluding the canal water), and measures upstream contribution. Each factor is rescaled 0 to 1 and combined using your weights. Only segments inside the selected sub-KHGs are scored. Then it selects the top share (top_fraction) of feasible segments as targets. Concession is applied afterwards as a filter, never inside the score.
Output
canal_segments with need_score, need_rank (1 = highest), feasible, selected; table qa_sensitivity.
Check
Map need_score: do the highest segments make sense on the ground? qa_sensitivity shows how stable the ranking is when weights change by 10 or 20 %. Low values mean the result depends strongly on your weights.

7 Sekat gap analysis and placement

Compares existing sekat with what the terrain needs and proposes new ones.

Does
Matches existing sekat to canals, then walks each canal from downstream to upstream and places a sekat each time the land has risen 0.40 m since the previous sekat (existing sekat restart the count). For each canal it calculates the required number of sekat and the IPG = existing / required (above 1 means enough).
Output
sekat_proposed (position, dist_down_m, z_land_m, spacing js_m, height ts_m, type standard or leaky/reinforced), sekat_existing_assessed (with IPG). IPG per canal is on canals_clean.
Check
Existing sekat that could not be matched to a canal (listed as a warning). Proposed sekat with an empty height mean the canal has no depth_m.

8 Network

Builds the canal network as a graph the computer can route over.

Output
network_nodes (junctions, sekat, river points) and network_edges (each canal piece, in both directions, with its start and end height).
Check
Usually nothing. It is there for inspection when a route looks wrong.

9 Water sources, targets and routes REVIEW

Finds how to bring river water to the priority canals at the lowest pumping cost.

Does
Sources are river and canal crossings (on perennial rivers or with a known dry-season level). Targets are the highest point of each group of selected segments, because water must reach the top. Routes are chosen to minimise length plus a penalty for going uphill, and shared canals are reused by several targets. An existing sekat without a gate blocks the route.
Output
pump_sources, pump_targets, pump_routes, qa_unreachable_targets.
Check
Targets with no route, in qa_unreachable_targets. The reason says why: blocked_by_ungated_sekat (add a gate), disconnected_from_river (fix the canal topology in stage 2), or no_path.

10 Water demand and pump stations

Calculates how much water is needed and where and how big the pumps must be.

Does
Demand = water deficit x peat area within the influence distance of the served canals, spread over the design period. Without a water deficit (no neraca air) it uses the required water-table rise x specific yield instead, and the design period you enter. The lift is the height difference between the river level and the target pool plus friction losses. Stations are placed so that no station lifts more than the maximum head, preferably at a sekat. Power = density x gravity x flow x head / efficiency.
Output
pump_stations (flow q_m3s, head h_m, power p_kw, units_needed), gates_required (sekat on a route that must be a gated type), and demand fields on pump_routes.
Check
Warnings about demand above the installed capacity (shortfall_m3s) and about single canal pieces that need more head than allowed.

11 Report

Collects everything into one readable summary.

Output
run_report.md and run_report.json next to the GeoPackage: all warnings, counts per stage, IPG per canal, weights and sensitivity, routing totals, the pump table, and the list of settings that are still null.

11 tahap

Setiap tahap membaca hasil tahap sebelumnya. Nama layer di bawah adalah layer yang Anda temukan di GeoPackage keluaran. Berkas yang bukan layer peta (raster, log) ada di folder bernama sama dengan berkas keluaran ditambah _work.

1 Muat dan validasi

Memeriksa bahwa data Anda dapat dipakai dan hanya menyimpan yang berada di dalam sub-KHG terpilih.

Dilakukan
Menolak DSM, memeriksa CRS setiap layer, memilih sub-KHG (N teratas menurut prioritas, menurut ID, atau semuanya; tanpa peringkat prioritas semua sub-KHG dipilih dengan prioritas yang sama), memotong semua data ke sub-KHG itu ditambah margin, dan mengubah atribut teks (frekuensi kebakaran, kelas gambut).
Keluaran
subkhg_selected, layer inputs_clipped_*, DTM dan raster kelembapan yang terpotong.
Periksa
Daftar peringatan. Perhatikan peringatan akurasi, nilai kebakaran atau gambut yang tidak terbaca, dan layer yang mencakup kurang dari 90 % wilayah.

2 Topologi kanal TINJAU

Membersihkan garis kanal agar membentuk jaringan yang tersambung. Penentuan rute air hanya bekerja pada jaringan yang tersambung.

Dilakukan
Menerapkan suntingan kanal Anda, menyambungkan ujung yang hampir bersentuhan, memecah garis di persimpangan, membuang duplikat, memangkas ujung pendek (jika diaktifkan), dan memeriksa bahwa setiap kanal tersambung ke sungai. Tidak ada yang dihapus tanpa catatan.
Keluaran
canals_clean ditambah layer masalah: qa_topology_gaps (ujung yang disambung), qa_topology_dangles (ujung bebas), qa_topology_disconnected (kanal tanpa sambungan ke sungai), qa_topology_issues (garis yang berpotongan sendiri atau tertutup), qa_topology_trimmed, qa_topology_edits.
Periksa
Buka layer masalah. Celah yang terlalu besar untuk disambung tampak sebagai dangle di dekat kanal lain. Perbaiki dengan menambah garis ke layer suntingan kanal (action = add) atau menghapus kanal yang salah (action = delete), lalu jalankan lagi. Suntingan yang sama memberi hasil yang sama setiap kali.

3 Analisis aliran

Menghitung ke mana air mengalir di atas lahan, hanya dipakai untuk penentuan rute.

Dilakukan
Membakar kanal ke dalam salinan DTM, menghilangkan cekungan kecil, dan menghitung akumulasi aliran (berapa banyak lahan yang mengalir ke setiap sel).
Keluaran
Berkas dtm_conditioned.tif dan flow_acc.tif di folder kerja.
Periksa
Peringatan tentang kanal yang memakai kedalaman bawaan, artinya depth_m tidak ada. DTM asli tidak pernah diubah; semua tinggi dan kemiringan berasal darinya.

4 Segmen

Memotong kanal menjadi bagian sepanjang paling besar 500 m, yang menjadi satuan penilaian.

Keluaran
canal_segments dengan seg_id yang stabil, length_m, dan status_mcda.
Periksa
Potongan yang lebih pendek dari 25 m mendapat status_mcda = 0: tetap ada di jaringan tetapi tidak dinilai.

5 Profil lahan dan arah aliran

Mengukur bagaimana lahan naik sepanjang setiap kanal.

Dilakukan
Membaca tinggi lahan di kedua tepi (6 m dan 10 m dari kanal, karena dasar kanal sendiri lebih rendah daripada lahan), menghaluskannya, menurunkan kemiringan, dan menentukan ujung mana dari setiap kanal yang berada di hilir. Kanal yang datar ditentukan dari jaraknya ke sungai terdekat.
Keluaran
canal_profiles (titik setiap 5 m), serta kolom baru pada canal_segments (z_up_m, z_down_m, i_lahan_pct) dan pada canals_clean (direction).
Periksa
Peringatan tentang kanal yang arahnya tidak dapat ditentukan, biasanya kanal yang tidak tersambung ke sungai mana pun.

6 Prioritasi segmen TINJAU

Mengurutkan segmen menurut seberapa besar kebutuhannya untuk dibasahi kembali.

Dilakukan
Untuk setiap segmen, mengambil kelas kebakaran dan kelas gambut yang mencakup panjang terbesar segmen itu, mengukur kekeringan di cincin sekitar kanal (tanpa air kanal), dan mengukur kontribusi dari hulu. Setiap faktor diskalakan 0 sampai 1 lalu digabung dengan bobot Anda. Hanya segmen di dalam sub-KHG terpilih yang dinilai. Kemudian porsi teratas (top_fraction) dari segmen yang layak dipilih sebagai sasaran. Konsesi diterapkan sesudahnya sebagai filter, tidak pernah di dalam skor.
Keluaran
canal_segments dengan need_score, need_rank (1 = tertinggi), feasible, selected; tabel qa_sensitivity.
Periksa
Petakan need_score: apakah segmen tertinggi masuk akal di lapangan? qa_sensitivity menunjukkan seberapa stabil peringkat ketika bobot berubah 10 atau 20 %. Nilai rendah berarti hasilnya sangat bergantung pada bobot Anda.

7 Analisis celah dan penempatan sekat

Membandingkan sekat yang ada dengan kebutuhan medan dan mengusulkan sekat baru.

Dilakukan
Mencocokkan sekat yang ada ke kanal, lalu menelusuri setiap kanal dari hilir ke hulu dan menempatkan sekat setiap kali lahan naik 0,40 m sejak sekat sebelumnya (sekat yang ada mengulang hitungan). Untuk setiap kanal dihitung jumlah sekat yang dibutuhkan dan IPG = ada / dibutuhkan (di atas 1 berarti cukup).
Keluaran
sekat_proposed (posisi, dist_down_m, z_land_m, jarak js_m, tinggi ts_m, tipe standard atau leaky/reinforced), sekat_existing_assessed (dengan IPG). IPG per kanal ada di canals_clean.
Periksa
Sekat yang ada yang tidak dapat dicocokkan ke kanal (tercantum sebagai peringatan). Sekat usulan dengan tinggi kosong berarti kanalnya tidak punya depth_m.

8 Jaringan

Menyusun jaringan kanal sebagai graf yang dapat dilalui perhitungan rute.

Keluaran
network_nodes (persimpangan, sekat, titik sungai) dan network_edges (setiap potongan kanal, dua arah, dengan tinggi awal dan akhirnya).
Periksa
Biasanya tidak perlu. Tahap ini ada untuk pemeriksaan ketika sebuah rute tampak keliru.

9 Sumber air, sasaran, dan rute TINJAU

Mencari cara membawa air sungai ke kanal prioritas dengan biaya pemompaan terendah.

Dilakukan
Sumber adalah persilangan sungai dan kanal (pada sungai permanen atau yang tinggi muka air musim kemaraunya diketahui). Sasaran adalah titik tertinggi dari setiap kelompok segmen terpilih, karena air harus mencapai bagian atas. Rute dipilih untuk meminimalkan panjang ditambah penalti naik tanjakan, dan kanal bersama dipakai ulang oleh beberapa sasaran. Sekat yang ada tanpa pintu air menghalangi rute.
Keluaran
pump_sources, pump_targets, pump_routes, qa_unreachable_targets.
Periksa
Sasaran tanpa rute, di qa_unreachable_targets. Kolom reason menjelaskan sebabnya: blocked_by_ungated_sekat (tambahkan pintu air), disconnected_from_river (perbaiki topologi kanal di tahap 2), atau no_path.

10 Kebutuhan air dan stasiun pompa

Menghitung berapa air yang dibutuhkan serta di mana dan sebesar apa pompanya.

Dilakukan
Kebutuhan = defisit air x luas gambut dalam jarak pengaruh kanal yang dilayani, dibagi sepanjang periode rancangan. Tanpa defisit air (tidak ada neraca air), dipakai kenaikan muka air yang dibutuhkan x hasil jenis, dengan periode rancangan yang Anda isi. Angkatan adalah selisih tinggi antara muka air sungai dan kolam sasaran ditambah kehilangan gesekan. Stasiun ditempatkan agar tidak ada stasiun yang mengangkat melebihi tinggi tekan maksimum, sebaiknya di sebuah sekat. Daya = massa jenis x gravitasi x debit x tinggi tekan / efisiensi.
Keluaran
pump_stations (debit q_m3s, tinggi tekan h_m, daya p_kw, units_needed), gates_required (sekat pada rute yang harus bertipe berpintu air), dan kolom kebutuhan pada pump_routes.
Periksa
Peringatan tentang kebutuhan di atas kapasitas terpasang (shortfall_m3s) dan tentang potongan kanal tunggal yang membutuhkan tinggi tekan lebih besar daripada yang diizinkan.

11 Laporan

Mengumpulkan semuanya dalam satu ringkasan yang mudah dibaca.

Keluaran
run_report.md dan run_report.json di samping GeoPackage: semua peringatan, jumlah per tahap, IPG per kanal, bobot dan sensitivitas, total rute, tabel pompa, dan daftar pengaturan yang masih null.

Review stops

After stages 2, 6 and 9 the tool stops on purpose. These are the points where a human decision matters most.

In the wizard

  1. The stage card shows Review needed and the stage's layers are on the map (open the layers listed in the stage description above).
  2. If something is wrong, fix the cause (a setting in the Decisions box, canal edits) and click Re-run this stage.
  3. If it is fine, click Accept and continue. The next stage unlocks.

In the Processing algorithms

  1. The run ends with a message such as "Stage 2 finished; inspect the QA layers... re-run with --accept 2". In QGIS this appears as a warning, not a failure.
  2. Open the output GeoPackage and look at the layers listed in the stage description above.
  3. If something is wrong, fix the cause (canal edits, weights, config) and run again.
  4. If it is fine, run again with that stage ticked under Review stages to accept. The tool continues from where it stopped and does not redo finished work.

If you change something after a stage ran

  • The wizard marks that stage and every later one Out of date, and you cannot accept them until you re-run. The stage records the settings it was run with, so this also catches a value you edited after the result was produced.
  • Re-run this stage on an earlier stage clears the results of all later stages, because they depend on it. The wizard asks first and also takes their layers off the map.
  • Warnings raised by a stage disappear when it is re-run, so the list always matches the current result.
  • Canal edits and the other input layers are read in stage 1. If you change them, re-run from stage 1, not stage 2.
Do not skip reviewAn unconnected canal in stage 2 or a wrong weight in stage 6 quietly changes everything after it. Tick all three stages at once only for a repeat run whose inputs you have already reviewed.

Titik tinjauan

Setelah tahap 2, 6, dan 9 alat berhenti dengan sengaja. Di titik-titik inilah keputusan manusia paling berarti.

Di wizard

  1. Kartu tahap menampilkan Perlu tinjauan Anda dan layer tahap itu sudah ada di peta (buka layer yang tercantum pada uraian tahap di atas).
  2. Jika ada yang salah, perbaiki penyebabnya (pengaturan di kotak Keputusan, suntingan kanal) lalu klik Jalankan ulang tahap ini.
  3. Jika sudah baik, klik Terima dan lanjutkan. Tahap berikutnya terbuka.

Di algoritma Processing

  1. Proses berakhir dengan pesan seperti "Stage 2 finished; inspect the QA layers... re-run with --accept 2". Di QGIS ini muncul sebagai peringatan, bukan kegagalan.
  2. Buka GeoPackage keluaran dan lihat layer yang tercantum pada uraian tahap di atas.
  3. Jika ada yang salah, perbaiki penyebabnya (suntingan kanal, bobot, konfigurasi) lalu jalankan lagi.
  4. Jika sudah baik, jalankan lagi dengan tahap itu dicentang di Review stages to accept. Alat melanjutkan dari titik berhenti dan tidak mengulang pekerjaan yang sudah selesai.

Jika Anda mengubah sesuatu setelah tahap dijalankan

  • Wizard menandai tahap itu dan semua tahap sesudahnya sebagai Usang, dan Anda tidak dapat menerimanya sebelum menjalankan ulang. Tahap mencatat pengaturan yang dipakainya, jadi ini juga menangkap nilai yang Anda ubah setelah hasilnya dibuat.
  • Jalankan ulang tahap ini pada tahap yang lebih awal menghapus hasil semua tahap sesudahnya, karena mereka bergantung padanya. Wizard bertanya dulu dan juga mencabut layernya dari peta.
  • Peringatan yang dimunculkan sebuah tahap hilang ketika tahap itu dijalankan ulang, sehingga daftarnya selalu sesuai dengan hasil terbaru.
  • Suntingan kanal dan layer masukan lain dibaca di tahap 1. Jika Anda mengubahnya, jalankan ulang dari tahap 1, bukan tahap 2.
Jangan lewati tinjauanKanal yang tidak tersambung di tahap 2 atau bobot yang salah di tahap 6 diam-diam mengubah semua yang sesudahnya. Centang ketiga tahap sekaligus hanya untuk proses ulang yang masukannya sudah Anda tinjau.
